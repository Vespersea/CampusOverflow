# 接口与错误码

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1` |
| 编码 | `application/json; charset=UTF-8` |
| 认证 | **Cookie 会话**（服务端会话存 Redis，ADR-003），非 JWT |
| CSRF | 写操作需带 CSRF token；先 `GET /api/v1/auth/csrf` 取，再放进请求头 |
| 分页 | `?page=0&size=20`，返回 `content / totalElements / totalPages / page / size` |
| 时间 | 全库 UTC，接口返回 ISO-8601 |
| 错误 | RFC 7807 `ProblemDetail`，业务码放在 `code` 字段 |
| 文档 | <http://localhost:8080/swagger-ui.html> |

## 2. 错误响应格式

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "不能给自己的内容投票",
  "code": "QA-1015"
}
```

- `detail` 是**给人看的中文说明**，前端可直接展示；
- `code` 是**给程序判断的稳定标识**，前端不要用 `detail` 字符串做分支；
- 状态由 `DomainException.suggestedStatus()` 决定，领域层不感知 HTTP。

前端处理建议：401 → 跳登录；403 → 提示无权限；409 → 提示刷新重试；429 → 提示稍后；其他 → 通用错误。

## 3. 错误码分段

| 段 | 含义 | HTTP | 例子 |
| --- | --- | --- | --- |
| `<CTX>-1xxx` | 参数/不变式校验失败 | 400 | `QA-1015` 不能给自己的内容投票 |
| `<CTX>-2xxx` | 状态冲突（当前状态不允许该操作） | 409 | `QA-2001` 该问题已采纳过最佳答案 |
| `<CTX>-3xxx` | 权限不足 | 403 | `ID-3001` 仅管理员可执行该操作 |
| `AUTH-401` | 未登录/会话过期 | 401 | — |
| `AUTH-403` | 无权访问该资源 | 403 | — |
| `AUTH-429` | 登录尝试过多（账号锁定） | 429 | — |
| `SYS-400` | 请求参数不合法（框架层兜底） | 400 | — |
| `SYS-409-CONCURRENT` | 乐观锁冲突，内容被他人修改 | 409 | — |
| `SYS-409-DUPLICATE` | 唯一约束冲突（多为重复提交） | 409 | — |
| `SYS-500` | 未预期异常（不暴露堆栈） | 500 | — |

上下文前缀：`ID-`（Identity）、`QA-`（Q&A）、`REP-`（Reputation）、`DIS-`（Discovery）。全库共 **76 个**业务码。

### 各段代表性错误码

| 码 | 说明 |
| --- | --- |
| `ID-1001` | 学号/工号应为 4–20 位字母或数字 |
| `ID-1004` | 密码长度应为 8–64 位 |
| `ID-1006` | 不能修改自己的角色 |
| `ID-2006` | 该用户已完成认证 |
| `ID-3002` | 仅教师或管理员可以创建课程 |
| `QA-1007` | 二级回复只支持一层，不能继续回复 |
| `QA-1011` | 已有回答的问题不能由提问者删除 |
| `QA-2001` | 该问题已采纳过最佳答案，不能更改 |
| `QA-3005` | 只有课程管理者可以认证回答 |
| `REP-1002` | 可用积分不足 |
| `REP-1006` | 发起人不能赢得自己的悬赏 |
| `REP-2001` | 悬赏已结束，不能重复操作 |
| `DIS-1001` | 每个关键词至少 2 个字符 |
| `DIS-3001` | 只有接收者本人可以标记通知已读 |

> 新增业务错误时：选对前缀 → 选对千位段 → 写一句用户能看懂的中文 → 在领域层抛 `DomainException`。**不要**在 Controller 里 `return ResponseEntity.badRequest()` 绕过统一处理。

## 5. 鉴权与角色

| 角色 | 典型权限 |
| --- | --- |
| 学生 | 提问、回答、评论、投票、采纳自己的问题 |
| 教师（课程管理者） | 建课、管成员、认证回答、发起悬赏、编辑/删除本课程内容 |
| 管理员 | 用户与角色管理、认证、对账、全局治理 |

权限校验分两层：**HTTP 层**（Spring Security 拦 `AUTH-401/403`）与**领域层**（如 `QA-3001` 只有提问者或课程管理者可以编辑）。两层都要有——HTTP 层管“有没有登录”，领域层管“这个人能不能做这件事”。

## 6. 用 curl 试一下

```bash
# 1) 取 CSRF
curl -c cookie.txt -b cookie.txt http://localhost:8080/api/v1/auth/csrf

# 2) 登录（把 <token> 换成上一步返回的值，并带上 X-XSRF-TOKEN 头）
curl -c cookie.txt -b cookie.txt -H "Content-Type: application/json" \
     -H "X-XSRF-TOKEN: <token>" \
     -d '{"account":"2024117147","password":"Passw0rd!"}' \
     http://localhost:8080/api/v1/auth/login

# 3) 当前用户
curl -b cookie.txt http://localhost:8080/api/v1/auth/me
```
