# 领域模型

本页是**业务规则速查**：哪条规则在哪个聚合里、违反时报什么错、事件怎么流。规则实现以代码为准，这里只做索引与解释。

## 1. Identity（身份与认证）

### 聚合

| 聚合 | 不变式 | 错误码 |
| --- | --- | --- |
| `User` | 学号/工号 4–20 位字母或数字 | `ID-1001` |
| | 昵称不含 `@` 与空格（`@` 留给提及语法） | `ID-1002` |
| | 邮箱格式合法 | `ID-1003` |
| | 密码 8–64 位（`PasswordPolicy`） | `ID-1004` |
| | 学生账号不能由管理员直接创建，必须走注册 | `ID-1005` |
| | 不能修改自己的角色、不能禁用自己 | `ID-1006` / `ID-1007` |
| | 认证是终态，重复认证报错 | `ID-2006` |
| `Course` | 课程代码 2–20 位字母/数字/连字符 | `ID-1010` |
| | 只有教师或管理员能建课 | `ID-3002` |
| | 不能修改课程教师的角色 | `ID-1013` |
| 角色 | 学生 / 教师 / 管理员；课程管理者 = 授课教师 + 管理员 | `ID-3001` |

### 为什么这些规则在领域层

它们都是**与存储无关的判断**：给一个用户名、密码、课程代码，能不能成立，只看规则本身。放到 `identity/domain` 后，`ArchUnit FF-1` 保证它们不依赖 Spring/JPA，测试是纯 JVM 毫秒级。

## 2. Q&A（问答核心）

### 聚合与状态

| 聚合 | 关键规则 | 错误码 |
| --- | --- | --- |
| `Question` | 标签 1–5 个，不能为空 | `QA-1004` / `QA-1005` |
| | 采纳只能发生一次，采纳后不可更改 | `QA-2001` |
| | 已有回答的问题，提问者不能删除（防“问完就删”） | `QA-1011` |
| | 只有提问者或课程管理者可编辑/采纳/删除 | `QA-3001` / `QA-3002` / `QA-3003` |
| | 软删除后不可再操作 | `QA-1012`（ADR-006） |
| `Answer` | 已删除的回答不能被采纳 | `QA-1010` |
| | 已被采纳的回答，回答者不能删除 | `QA-1013` |
| | 认证（endorsement）是终态，重复认证报错 | `QA-2002` / `QA-3005` |
| | 只有回答者或课程管理者可编辑/删除 | `QA-3004` / `QA-3006` |
| `Vote` | 一人一票，可改投（+1 ↔ −1）或撤销 | — |
| | 不能给自己投票 | `QA-1015` |
| | 投票值只能是 `+1` / `-1` | `QA-1016` |
| `Comment` | 二级回复只支持一层（评论的评论不能再被回复） | `QA-1007` |
| | 回复必须挂在被回复评论的同一目标下 | `QA-1008` |

### 采纳带来的连锁反应

采纳不是“改个字段”，它触发一条链：**+15 声誉 → 徽章 → 悬赏结算 → 通知 → 搜索投影**。因此采纳在同一个事务里写 `outbox_event`，后续全部异步。

## 3. Reputation（声誉与激励）

### 积分模型

`ReputationAccount` 用**账户 + 流水**双写，二者同事务：

- **可用积分** = 可用于发起悬赏的部分；发起悬赏时**冻结**，结算/退款时解冻；
- 余额**不允许为负**（`REP-1001` 初始积分、`REP-1002` 可用积分不足）；
- 声誉**不直接赋值**，只通过流水追加，且“余额 = 流水之和”由每日对账校验。

`ReputationRulebook` 里的数值规则：

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 初始积分 | 1000 | 教师/管理员开户 |
| 采纳奖励 | +15 | **自问自答记 0**，防止刷分 |
| 投票增量 | 新效果 − 旧效果 | 改投不会重复加分，撤销会扣回 |
| 每日正向上限 | 200 | ADR-009：冻结积分模型，超出部分不累加 |
| 徽章 | `FIRST_ACCEPTED` 等 | 发放前做存在性检查，保证幂等 |

`AcademicTerm` 把时间切成**学期 / ISO 周 / 月**三种键，排行榜因此有周榜、月榜、学期榜、总榜。

### 悬赏 `Bounty`

```
OPEN ──(采纳)──▶ AWARDED     终态，不可回退
  └───(到期)──▶ EXPIRED      终态；积分退回发起人
```

| 规则 | 错误码 |
| --- | --- |
| 悬赏积分需在允许区间内 | `REP-1003` |
| 悬赏时长 1–N 天 | `REP-1004` |
| 已删除或已有采纳的问题不能发起悬赏 | `REP-1005` |
| **发起人不能赢得自己的悬赏**（自答则退款） | `REP-1006` |
| 终态不可重复操作 | `REP-2001` |
| 仅课程管理者可发起 | `REP-3001` |

### 一致性与幂等

| 场景 | 手段 |
| --- | --- |
| 发件箱至少一次投递 | 账本唯一键 `(eventId, userId, reason)` |
| 事件重复消费 | `processed_event` 表（`ProcessedEventStore`） |
| 徽章重复发放 | 存在性检查 |
| 榜单重复计入 | `ReputationChangedEvent` 幂等去重 |
| 余额与流水漂移 | 每日对账任务，指标 `co_reputation_mismatches` |

## 4. Discovery（发现与通知）

| 聚合/策略 | 规则 | 错误码 |
| --- | --- | --- |
| `SearchQuery` | 每个关键词至少 2 个字符（ngram 最小词元） | `DIS-1001` |
| | 关键词不超过 50 字符、最多 5 个词 | `DIS-1002` |
| | 规范化时剔除全文检索运算符，防注入/语法错误 | — |
| `MentionParser` | `@昵称` 去重，单条内容最多 5 人 | — |
| `Notification` | 只有接收者本人可以标记已读 | `DIS-3001` |
| | 幂等键 `(sourceEventId, recipientId)` | — |
| `RelatedQuestionPolicy` | Jaccard 相似度排序，得分/采纳数降序 | — |

`SearchIndexProjector` 消费 9 类事件更新搜索投影，`NotificationProjector` 消费 6 类事件生成通知，两者都用 `ProcessedEventStore` 去重。

## 5. 事件目录（`-api` 中的集成事件）

| 事件 | 发布方 | 主要订阅方 |
| --- | --- | --- |
| `UserRegisteredEvent` | Identity | Reputation（开户）、Discovery |
| `QuestionPostedEvent` / `QuestionEditedEvent` | Q&A | Discovery（索引/通知） |
| `AnswerSubmittedEvent` | Q&A | Discovery（通知提问者/关注者） |
| `AnswerAcceptedEvent` | Q&A | Reputation（+15、徽章、悬赏）、Discovery（通知、投影） |
| `AnswerEndorsedEvent` | Q&A | Reputation、Discovery |
| `VoteCastEvent` | Q&A | Reputation（差值结算）、Discovery |
| `CommentPostedEvent` | Q&A | Discovery（通知、@提及） |
| `ContentDeletedEvent` | Q&A | Discovery（撤索引）、Reputation |
| `BountyOpenedEvent` / `BountyAwardedEvent` / `BountyClosedEvent` | Reputation | Discovery |
| `ReputationChangedEvent` | Reputation | Discovery（榜单/档案）、通知 |
| `BadgeAwardedEvent` | Reputation | Discovery（通知） |

基础设施：`IntegrationEvent`（契约）、`IntegrationEventPublisher`、`OutboxIntegrationEventPublisher`（写发件箱）、`ProcessedEventStore` / `JdbcProcessedEventStore`（消费去重）、`EventIds`（事件 id 生成）。

## 6. 读模型与投影

| 读侧 | 来源表 | 谁维护 |
| --- | --- | --- |
| 搜索 | 搜索投影表（`ngram` 全文索引） | `SearchIndexProjector` |
| 通知 | `notification` | `NotificationProjector` |
| 排行榜 | 榜单快照/`ReputationChanged` 增量 | `LeaderboardService` |
| 积分流水 | 账本表 | `ReputationAccount` 写入，查询只读 |

> 投影表是**可重建**的：清空后重放事件即可恢复，这是把读模型和写模型分开的收益。
