# 架构与模块

## 1. 一句话架构

**模块化单体（Modular Monolith）+ 领域驱动设计**：一个进程、一个数据库，但内部按限界上下文和 DDD 分层切成 27 个 Maven 模块，边界由**编译依赖**和 **ArchUnit 规则**双重看守。业务上要拆微服务时，切分线已经画好（ADR-001）。

## 2. 27 个模块怎么来的

```
backend/pom.xml                                  ← 父 POM（版本、插件、JaCoCo 门禁）
├── co-shared-kernel/                            ← 共享内核：领域异常、Actor、事件契约、分页
├── co-identity/                                 ← 上下文聚合 POM
│   ├── co-identity-api/                         ← 发布语言（跨上下文唯一入口）
│   ├── co-identity-domain/                      ← 聚合、值对象、领域事件、仓储接口
│   ├── co-identity-application/                 ← 用例编排、事务、事件发布
│   ├── co-identity-infrastructure/              ← JPA/Redis/JDBC 适配器
│   └── co-identity-interfaces/                  ← REST 控制器
├── co-qa/          （同样 5 层）
├── co-reputation/  （同样 5 层）
├── co-discovery/   （同样 5 层）
└── co-bootstrap/                                ← 启动类、安全链、全局异常、Flyway、ArchUnit 测试
```

计数：`1 父 + 1 shared-kernel + 1 bootstrap + 4 上下文 ×(1 聚合 + 5 层) = 27`。

## 3. 五层各放什么

| 层 | 放什么 | 禁止什么 |
| --- | --- | --- |
| `-api` | DTO、对外接口、跨上下文事件契约 | 依赖 Spring/JPA/Jackson；依赖任何实现层 |
| `-domain` | 聚合根、实体、值对象、领域服务、领域事件、仓储**接口** | 依赖任何框架注解（Spring、JPA、Validation、Hibernate） |
| `-application` | 用例服务、事务边界、事件发布、调用他上下文的 `-api` | 直接依赖他上下文的 domain/application |
| `-infrastructure` | JPA 实体、仓储实现、Redis、JDBC 读模型、外部系统适配 | 被 domain 反向依赖 |
| `-interfaces` | Controller、请求校验、DTO 映射、HTTP 语义 | 承载业务规则 |

依赖方向（由外向内，内层不知道外层）：

```
interfaces ──▶ application ──▶ domain ◀── infrastructure
                                   ▲
                          shared-kernel（异常/事件契约/Actor/分页）
```

## 4. ArchUnit 守的六条线

在 `co-bootstrap/src/test/java/com/campusoverflow/architecture/ArchitectureTest.java`：

| 规则 | 内容 | 违反后果 |
| --- | --- | --- |
| **FF-1** | `..domain..` 不得依赖 `org.springframework..`、`jakarta.persistence..`、`jakarta.validation..`、`org.hibernate..`、`com.fasterxml.jackson..`、`io.swagger..` | 领域模型无法脱离容器单测，直接失败 |
| **FF-4** | 依赖必须由外向内：`Interfaces/Application/Infrastructure` 不得被 `Domain` 依赖 | 越层调用，架构腐化 |
| **FF-5** | `*.api..` 只能依赖 `java..`、shared-kernel、其他 `*.api..` | 发布语言变重，跨上下文耦合 |
| 跨上下文 | `com.campusoverflow.<A>..` 只能依赖 `<B>.api..`，不得碰 `<B>.domain/application/interfaces/infrastructure` | 上下文边界被打穿 |
| 无环 | 上下文之间不得出现循环依赖 | 无法独立演进 |
| 表名前缀 | `identity_*` / `qa_*` / `rep_*` / `dis_*` | 同库多上下文时表归属不清 |

运行：

```bash
mvn test -pl co-bootstrap -Dtest=ArchitectureTest
```

> 另外 ADR-008 要求 **JPA 实体 ≠ 领域模型**：`infrastructure` 里有独立的 `@Entity`，与 `domain` 的对象做显式映射。领域层因此可以纯 POJO 单测。

## 5. 共享内核里有什么

`co-shared-kernel` 被所有上下文依赖，所以只放**稳定的抽象**：

- `DomainException`：携带 `code`（如 `QA-1015`）与 `suggestedStatus()`（映射 HTTP 状态）；
- `Actor`：当前操作者（用户 id、角色），由认证层注入；
- 事件契约：跨上下文发布/订阅的事件载荷；
- 分页对象：统一的 `PageResult`。

> 放进去的东西等于全系统可见，**任何业务规则都不该进共享内核**。

## 6. 一次跨上下文协作怎么走

```
Controller (interfaces)
   └─▶ ApplicationService (application)  @Transactional
          ├─ 加载聚合 (domain) → 执行业务规则（不满足就抛 DomainException）
          ├─ 仓储保存 (domain 接口 / infrastructure 实现)
          ├─ 写发件箱 outbox_event（同事务）
          └─ 返回 DTO
中继（bootstrap）
   └─▶ 读 outbox → 投递事件 → 各上下文 Handler（必须幂等）
```

关键点：**跨上下文不直接调用对方的 application/domain**，只发事件或调 `-api`。事件落 `outbox_event` 与业务同事务，因此“业务成功但事件丢”不会发生。

## 7. 新增一个功能的推荐顺序

1. `-api`：先定 DTO 与接口（契约优先，ADR-007），前端可以并行；
2. `-domain`：写聚合方法 + 不变式，**先写测试**（领域测试就是规格）；
3. `-application`：编排用例、划事务边界、决定发什么事件；
4. `-infrastructure`：补仓储实现/查询（多数情况已有适配器，只需对上新方法）；
5. `-interfaces`：加 Controller 方法与校验；
6. 跑 `mvn test` + `ArchitectureTest`，再看覆盖率是否还过门禁。

## 8. 为什么不是微服务

| 维度 | 模块化单体（当前） | 微服务 |
| --- | --- | --- |
| 部署 | 一个 jar | N 个服务 + 网关 + 注册中心 |
| 事务 | 本地事务即可（账本一致性容易保证） | 需要 Saga/最终一致 |
| 边界 | Maven + ArchUnit | 网络边界天然隔离 |
| 拆分时机 | 某个上下文成为瓶颈时再拆 | 一开始就要定 |

课程项目选前者：**先把边界画对，再谈分布式**。ADR-001 记录了完整权衡。

## 9. 前端结构

```
frontend/src/
├── api.ts                 单文件 API 客户端（fetch + ProblemDetail 解析）
├── auth.tsx / auth-context.ts   登录态 Context
├── App.tsx                路由表
├── types.ts               与后端 DTO 对应的类型
├── styles.css
└── pages/
    ├── LoginPage.tsx          登录 / 注册
    ├── QuestionListPage.tsx   列表 + 搜索
    ├── QuestionDetailPage.tsx 详情 + 投票 + 采纳 + 评论
    ├── AskPage.tsx            提问
    ├── LeaderboardPage.tsx    排行榜
    ├── NotificationsPage.tsx  通知中心（30 秒轮询）
    └── BountyDialog.tsx       发起悬赏 + 倒计时
```

前端不引入状态管理库：登录态用 Context，页面数据用局部 state + `api.ts`。
