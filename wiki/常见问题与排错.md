# 常见问题与排错

## 1. 三分钟自查表

| 症状 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 启动就抛 `UnsupportedOperationException: TODO(S2)` | 该方法还没实现 | 正常现象，去实现它（见任务清单） |
| `mvn test` 一片红 | 骨架里 107 个 TODO 未完成 | 同样正常；看失败信息定位到具体方法 |
| 后端起不来：`Connection refused` 连 MySQL | 中间件没起 | `docker compose -f deploy/docker-compose.yml up -d mysql redis` |
| 端口被占用 | 已有实例在跑 | 改 `SERVER_PORT`，或先停旧进程 |
| 登录后立刻 401 | Cookie 没带上 / 域名不一致 | 前后端同源访问；检查浏览器 Cookie 是否被拦 |
| 写操作 403 `AUTH-403` | 缺 CSRF token | 先 `GET /api/v1/auth/csrf`，再带 `X-XSRF-TOKEN` |
| 中文搜索搜不到 | 用了自建 MySQL，没 ngram | 用 compose 的 MySQL（`ngram_token_size=2`，关闭停用词） |
| 声誉不变化 | 事件还在发件箱里，或被消费端拒绝 | 查 `outbox_event` 的 `last_error` |
| 同一次采纳加了两次分 | 消费端不幂等 | 用账本唯一键 `(eventId,userId,reason)` / `processed_event` |
| CI 红着推上去了 | 本地没跑 `mvn verify` | 先本地跑，再推 |
| `mvn verify` 报 Docker 环境错误 | Testcontainers 找不到 Docker | 启动 Docker Desktop；或先用 `-DskipITs` |
| 前端 `tsc` 报 `possibly undefined` | `noUncheckedIndexedAccess` 开启 | 加判空；别用 `as any` 糊过去 |

## 2. 详情：为什么启动会报 TODO

骨架把领域方法留成了：

```java
throw new UnsupportedOperationException("TODO(S2): Question.accept(...)");
```

这不是“环境没配好”，而是**需求待办**。想确认自己没弄坏环境，跑一个已经实现的用例（如登录）即可。

## 3. 详情：声誉为什么“不动”

声誉是**异步结算**的，链路有三段，任何一段卡住都表现为“分数不变”：

```
业务操作 → 同一事务写 outbox_event → 中继读取投递 → 消费端幂等处理 → 账本追加
```

排查顺序：

1. `select * from outbox_event order by created_at desc limit 20;` —— 事件有没有落库？
2. 看 `last_error`、`attempts` —— 投递失败会记在这里；
3. 看 `processed_event` —— 消费端是否已处理（重复投递被去重）；
4. 看账本表 —— 有没有这条流水；
5. 看 `co_reputation_mismatches` —— 余额与流水是否已经不平。

## 4. 详情：中文搜索为什么没结果

MySQL 的中文全文检索依赖 `ngram` 分词器，compose 里已经设了：

```yaml
command:
  - --ngram-token-size=2
  - --innodb-ft-enable-stopword=0
```

如果你换了自建库而没同步这两个参数：

- 分词成整句 → 搜“采纳”匹配不到“最佳答案采纳”；
- 停用词把 `ngram` 词元丢掉 → 短词永远搜不到。

另外业务层还有两道限制（有意为之）：**每个关键词至少 2 个字符**（`DIS-1001`）、**最多 5 个词 / 50 字符**（`DIS-1002`）。

## 5. 详情：事件重复导致加分两次

发件箱语义是 **at least once**，所以消费端必须幂等。三种做法（本项目都用）：

| 场景 | 幂等键/机制 |
| --- | --- |
| 账本追加 | 唯一键 `(event_id, user_id, reason)` |
| 通用消费去重 | `processed_event` 表（`ProcessedEventStore`） |
| 徽章发放 | 发放前查“是否已拥有” |
| 通知生成 | `(sourceEventId, recipientId)` |

自己写新消费者时，**第一件事是决定幂等键**，不是写业务逻辑。

## 6. 详情：Windows 本地环境

| 问题 | 处理 |
| --- | --- |
| `mvn` 命令找不到 | 装 Maven 并配 `MAVEN_HOME`/`PATH`，或直接用 IDE 内置 Maven |
| 中文路径导致插件异常 | 工程放短路径，如 `D:\work\campus-overflow-student` |
| 控制台中文乱码 | `-Dfile.encoding=UTF-8`；或 `chcp 65001` |
| Docker Desktop 占内存 | 只起 mysql/redis 两个容器，别把 observability 也拉起来 |
| 端口 3306 被本机 MySQL 占用 | 停本机服务，或改 compose 的映射端口并同步 `DB_PORT` |

## 7. 排错方法论：先分层，再猜原因

遇到问题先问“哪一层”，而不是直接翻代码：

1. **进程层**：服务起来了吗？`curl /actuator/health`
2. **依赖层**：MySQL/Redis 通吗？`docker compose ps`、`docker compose logs`
3. **数据层**：表结构与迁移对吗？Flyway 有没有跑过；`outbox_event` 有数据吗
4. **领域层**：返回的是业务码还是 500？`code` 字段一看就知道是哪条规则
5. **前端层**：请求发出去了吗？浏览器 Network 里看状态码与响应体

**错误码就是最好的线索**：`QA-1015` 说明规则拦住了，`SYS-500` 才需要看堆栈。
