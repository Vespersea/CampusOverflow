## 一分钟认识这个系统

四个限界上下文（Bounded Context），一个模块化单体：

- **Identity** —— 账号、登录、课程与角色（学生 / 教师 / 管理员），是完整实现的**参考范例**；
- **Q&A** —— 提问、回答、评论、标签、投票、采纳最佳答案；
- **Reputation** —— 积分账本、徽章、悬赏、排行榜、每日对账；
- **Discovery** —— 中文全文检索、相关问题、@提及、通知中心。

一次典型的跨上下文协作：

```
注册(Identity) ──IdentityRegistered──▶ 开户 1000 分(Reputation)
提问 ──▶ 回答 ──▶ 采纳(AnswerAccepted)
                 ├─▶ 声誉 +15（自问自答 0）
                 ├─▶ 徽章 FIRST_ACCEPTED
                 ├─▶ 悬赏结算 / 关闭
                 ├─▶ 搜索投影更新(Discovery)
                 └─▶ 通知作者(Discovery)
```

## Wiki 与 docs/ 的分工

| 位置 | 放什么 | 特点 |
| --- | --- | --- |
| **Wiki（本处）** | 导览、怎么用、为什么这样设计、规则速查 | 给人看，可点击导航，随代码走 |
| `docs/adr/` | 架构决策记录（决策背景、备选方案、后果） | 一份决策一个文件，不改写 |
| `docs/storming/` | 事件风暴、上下文映射、聚合清单、统一语言 | 领域建模原始材料 |
| `docs/backlog/` | 用户故事、故事地图、Gherkin 场景 | 需求基线 |
| `docs/team/`、`docs/retro/`、`docs/ops/` | 团队章程、评审清单、Sprint 回顾、运维手册 | 过程证据 |
| `README.md` | 五分钟跑起来 + 验收门槛 | 入口说明书 |

> 原则：Wiki **不复述** docs/ 正文，只给结论、给索引、给“该点哪儿”。发现两处矛盾时，以 `docs/` 与代码为准，并回来修这一页。
