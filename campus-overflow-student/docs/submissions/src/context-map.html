编号双方模式说明
①co-identity → co-qa客户-供应商 + 发布语言co-qa 是客户(下游),只通过 co-identity-api 模块(发布语言)查询用户/课程/课程角色;禁止直连 Identity 持久化表
②co-qa → co-reputation客户-供应商 + 集成事件Reputation 订阅 Q&A 的 VoteCast/AnswerAccepted/AnswerEndorsed 等事件记账与发徽章;需上下文信息时仅经 co-qa-api 查询
③co-qa → co-discovery事件投影 + 防腐层(ACL)Discovery 是纯下游:在防腐层(SearchIndexProjector/NotificationProjector)把 Q&A 事件翻译为搜索文档与通知,不经 Q&A 任何查询接口
④co-identity → co-reputation集成事件(事件驱动)订阅 UserRegisteredEvent 为新用户开户,教师角色发放 1000 悬赏积分;双方无同步调用
⑤co-reputation → co-discovery集成事件(事件驱动)订阅 BadgeAwardedEvent(徽章通知)与 ReputationChangedEvent(可选),仅做通知投影
⑥全部上下文 ↔ co-shared-kernel共享内核(SK)共享领域异常体系、分页模型、事件契约基类;变更必须经全团队评审
⑦co-bootstrap → 全部上下文组合根装配全部模块:Spring 装配、安全过滤链、OutboxRelay、定时任务;不包含业务逻辑
边界规则(由 ArchUnit 强制):① 跨上下文调用只能经对方 -api 模块或集成事件;② Q&A 是事件唯一业务源头,下游故障不影响主流程(发件箱最终一致);③ 下游不回调上游写操作;④ 共享内核只放最小集合。 图例:实线箭头 = 依赖方向(箭头指向被依赖方)· 虚线箭头 = 集成事件订阅 · 灰色细线 = 组合根装配。
